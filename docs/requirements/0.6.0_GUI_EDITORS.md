# 0.6.0 GUI editors (Neovide and VS Code scratch buffers)

Status: built 2026-10-19 (task 42, ADR 0010). Checked live on this Mac except the key presses themselves.

## Goal

Neovim as a GUI app, mainly to open a blank buffer as fast as possible, with no intention of saving it, but with the option to save it later. Two ways, both in the `gui` group, so every machine gets both:

- **Neovide**: the real LazyVim config (`~/.config/nvim`) in a GUI window.
- **VS Code** with vscode-neovim: VS Code's untitled files with Neovim's normal mode.

## Neovide

- **Cask** `neovide-app` (`neovide` is the old name).
- **Hotkey** Ctrl+Opt+Cmd+N (Karabiner rule in every profile): a new Neovide window with its own Neovim, in `~`. When Neovide runs, `neovide --reuse-instance --new-window` hands the request to the running app (about 60 ms); otherwise `open -a Neovide`. A handed-off request drops the Neovim arguments after `--`, so a scratch window can't be marked by an argument: see the next point.
- **Scratch window** (`lua/config/neovide.lua`): a Neovide window started without files. Its empty buffer is `buftype=nofile`, without a swap file, so typing in it never makes Neovim ask to save, and closing the window throws it away. No dashboard in it (`plugins/ui.lua`). A Neovide window opened with files (`neovide <file>`, Finder's Open With) is an ordinary one.
- **Keeping a scratch buffer:** `:Keep [file]`, Cmd+S or `<leader>ww` (buffer-local) asks for a name when none is given, saves with `:saveas` and turns it into an ordinary file buffer (`buftype` cleared, filetype detected from the name). Cmd+S and `<leader>ww` write ordinary buffers as usual.
- **macOS shortcuts** in Neovide: Cmd+S save, Cmd+W close the window (`confirm qa`: asks only for real unsaved files), Cmd+C copy (visual), Cmd+V paste (normal, visual, insert, command line, terminal). Option is Meta on both sides, as iTerm's Option.
- **Look:** IntoneMono NF 16 with 8 px line spacing, close to the iTerm `16` profiles. Colour scheme: the first-run `theme`. Light/dark: Neovide sets `'background'` from the macOS appearance (0.16+), so `config/follow_terminal.lua` does nothing in Neovide (there's no terminal to ask).
- `~/.config/neovide/config.toml`: `fork = true`, so `neovide <file>` from a shell returns at once.
- Neovim starts in about 22 ms in a scratch window (`--startuptime`, headless).

## VS Code

- **Hotkey** Ctrl+Opt+Cmd+V: `code -n`, a new window with an untitled file (`workbench.startupEditor: newUntitledFile`, already set). `code --file-uri untitled:…` opens nothing, so there is no way to add an untitled tab to an existing window from outside.
- **Extension** `asvetliakov.vscode-neovim`, with `neovimExecutablePaths.darwin` set to Homebrew's `nvim` and the extension host affinity its README recommends.
- **Neovim side:** LazyVim's `vscode` extra (`lazyvim.json`), which only loads the editing plugins when `vim.g.vscode` is set (no effect in terminal Neovim). `follow_terminal.lua` does nothing in VS Code.
- **Scratch behaviour is VS Code's hot exit** (default `onExit`): Cmd+Q keeps every untitled file and restores it on the next launch, without asking. Closing a single window with unsaved untitled files asks to save (Don't Save = Cmd+Delete): VS Code only hot-exits a closed window when it has a folder open.

## Tests

- **Host** (`test/run.sh --host-only`, 103 pass): Brewfile and managed-file snapshots include the cask and the new files.
- **Headless on this Mac** (copy of `~/.config/nvim` with the changes): with `g:neovide` and no files, the buffer is `nofile`, `:Keep <path>` writes it and makes it a `markdown` buffer, the buffer-local `<leader>ww` goes away; with a file, no scratch; plain Neovim and VS Code mode (stub `vscode` module) start without errors, including the keymaps.
- **Live on this Mac** (2026-10-19, hotkey commands run with Karabiner's minimal environment, windows driven through `nvim --server`): Neovide cold start, then a second window in the same app, both scratch with the right font and scheme; typed text, Cmd+W closed with no prompt; Cmd+S asked for a name, saved, became markdown; VS Code opened `Untitled-1`, vscode-neovim ran Homebrew's `nvim` in `vscode` mode (9 plugins, no messages).
- **By hand, still to do:** pressing the hotkeys themselves (Karabiner only sees real key presses), light/dark switch in Neovide, VS Code Cmd+Q restore.

## Not covered

- Neovide scratch buffers are gone when the window closes (by design). Use VS Code when the text should survive by itself.
- The VM suite doesn't check Neovide or the vscode-neovim extension beyond the Brewfile and the extension list.
