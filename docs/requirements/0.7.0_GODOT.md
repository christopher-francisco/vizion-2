# 0.7.0 Godot in LazyVim

Status: built 2026-10-19 (task 43). LazyVim config only; `nvim-legacy` left as is.

## Goal

Edit Godot projects (GDScript, shaders, scenes and resources) in LazyVim with highlighting and the GDScript language server, and let Godot open scripts in the Neovim already running in the project. Godot itself is a cask in the `personal` group (task 34); the Neovim part is in the shared config, so every machine has it, and it does nothing outside a Godot project.

## Design

- **No LazyVim extra:** LazyVim has none for Godot (checked 2026-10-19: 47 `lang.*` extras upstream, no issue or PR), so it is three small additions to the existing specs, and no new plugin.
- **Treesitter** (`plugins/treesitter.lua`): `gdscript`, `gdshader`, `godot_resource`. Neovim detects `.gd` and `.gdshader`; nvim-treesitter maps `.tscn`/`.tres` (`gdresource`) to `godot_resource`.
- **LSP** (`plugins/lsp.lua`): nvim-lspconfig's `gdscript` with `mason = false`. The server runs inside the Godot editor (TCP `127.0.0.1:6005`, or `$GDScript_Port`), so it works only while Godot has the project open; otherwise opening a `.gd` file prints `Could not connect to 127.0.0.1:6005`. `gdshader_lsp` is left out (third-party binary, not in Homebrew).
- **External editor** (`config/autocmds.lua`): Neovim started inside a Godot project (`project.godot` in the working directory or above) listens on `<project>/.godot/nvim.sock`. `.godot/` is Godot's own cache folder, ignored by Godot projects. The first Neovim in the project takes the socket; later ones skip it silently. macOS limits socket paths to 104 bytes: a longer path gives a warning and no socket. Godot's setting (set by hand, see README): exec path `nvim`, flags `--server {project}/.godot/nvim.sock --remote-send "<C-\><C-N>:e {file}<CR>:call cursor({line}, {col})<CR>"`.

## Tests

By hand on this Mac, 2026-10-19 (Godot 4.7.2, Neovim 0.12.6):

- Parsers installed; `.gd` → `gdscript`, `.tscn` → `gdresource`, both highlighted.
- Headless Godot editor on port 6099 (`--lsp-port`, `GDScript_Port=6099`): `gdscript` attached with the project as root and reported the type error in a test script. Without Godot: the connect message, no other error.
- LazyVim in a private tmux server, started in a test project: the socket appeared, Godot's command opened the script at line 4, column 6; a second Neovim in the project started without a socket and without an error; an over-long path gave the warning.

## Not covered

- Godot's editor settings (`editor_settings-4.*.tres`, rewritten by Godot) are not managed: set the external editor by hand.
- Godot doesn't bring the terminal to the front when it opens a script.
- Debugging (DAP) and running scenes from Neovim. habamax/vim-godot, whose only addition is run commands, was rejected (ADR 0011).
