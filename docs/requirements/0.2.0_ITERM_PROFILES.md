# 0.2.0 — iTerm profiles: themes, sizes and a default per machine

- **Status:** Accepted (2026-10-16). Decision in ADR 0006; supersedes the profile layout of `0.1.0_CHEZMOI_DESIGN.md` ("iTerm2") and R6.1's "one file per colour scheme". Verified in a VM before building (see "Verified").

## Problem

1. **Too many near-identical profiles.** 17 profiles in 7 files. The 7 Tokyonight profiles have the same colours and differ only in font size and line spacing; two are identical (`- Big` and `- 5k`: 16pt, 1.5). Names say nothing about size (`- 4k small` is the smallest, 11pt; `- Small` is 13pt). Every profile repeats keys that never vary (`Non Ascii Font`, `Minimum Contrast`, `Horizontal Spacing`, `Transparency`, `Blur`, `Shortcut`, `Background Image Location`).
2. **Light and dark are separate profiles** (`Everforest Light`/`Dark`), and each tells Neovim which one it is through `Initial Text: export THEME=…`, which only works in the first shell of a session and never reaches tmux.
3. **The default profile is the same on every machine.** The work laptop is almost always on a big monitor and wants a larger font. The default is `Default Bookmark Guid` in the main plist, which iTerm reads straight from the repo and saves back into on quit, so it can't be templated, and a per-machine `defaults write` would flip the value in git on every quit. The profile files are symlinks into the repo (ADR 0004), so they can't differ per machine either.

## Proposal

### Three levels: Base → theme → size

```
iTerm defaults               regular profile in the slim plist, fixed GUID, no settings; tag "base"
Base                         keyboard, terminal, behaviour + the keys every profile repeats today
├─ Tokyonight                light + dark colours, font family; tag "base"
│  ├─ Tokyonight 11          Normal Font + Vertical Spacing + monitor tags
│  ├─ Tokyonight 13
│  ├─ Tokyonight 16
│  └─ Tokyonight 20
└─ Everforest                (same shape)
   └─ Everforest 11 … 20
This Mac                     rendered per machine; parent = one size profile
```

- **`iTerm defaults`** is a regular (not dynamic) profile, so it exists before any dynamic file loads, and its only job is to be `Base`'s parent. A dynamic profile without a parent inherits from *the default profile*: with a dynamic default, `Base` would inherit from `This Mac` → `Tokyonight 16` → `Tokyonight` → `Base` on every reload (see "Verified"). It also stops iTerm creating its own regular `Default` profile with a random GUID on each new machine.
- **Every profile names its parent by both `Dynamic Profile Parent Name` and `Dynamic Profile Parent GUID`.** A child that sets only the name inherits its parent's parent GUID, and iTerm's rewrite then diffs against the wrong profile and copies the theme's colours into the size profile.
- **Parents load first**: `00-base.json` first, `zz-` last, and within a file the theme before its sizes.

- **Theme profiles** (`Tokyonight`, `Everforest`) hold only colours and the font family. They're parents, not meant to be opened, so they carry the tag `base` to sit in the same submenu as `Base`, out of the way.
- **Size profiles** set `Normal Font` (family + size: iTerm keeps both in one string, so each theme has its own sizes) and `Vertical Spacing`, and are tagged with the monitors they're for. Named by point size (plus `tight` for the less spaced variant), so the name says what you get.
- **Monitor tags** drive the Profiles menu, as today (`Profiles > retina > Tokyonight 13`). A size used on several monitors is one profile with several tags instead of one copy per monitor. Each profile also has its theme tag (`tokyonight`, `everforest`) so `Profiles > tokyonight` lists every size.

Small and big per monitor, from today's profiles:

| Monitor tag | Small | Big | Today |
|---|---|---|---|
| `retina` (MacBook) | 13 | 16 | `(Night)` 13 / 1.5, `- Big` 16 / 1.5 |
| `2k` | 13 | 20 | `- Small` 13 / 1.33, `- 2k` 20 / 1.7 |
| `4k` | 11 | 16 | `- 4k small` 11 / 1.5, `- 4k` 16 / 1.7 |
| `studio-display` (5K) | 13 | 16 | only `- 5k` 16 / 1.5 (tag `5k`); small is new |

Six size profiles per theme. A size used by several monitors is shared only where their line spacing matches too; where it doesn't, a `tight` variant keeps the monitor's spacing (line spacing decides how much of the screen height is left over below the last line, e.g. under tmux's status bar, so it's tuned per monitor):

| Profile | Font | Line spacing | Tags |
|---|---|---|---|
| `Tokyonight 11` | IntoneMonoNF 11 | 1.5 | `tokyonight`, `4k` |
| `Tokyonight 13` | IntoneMonoNF 13 | 1.5 | `tokyonight`, `retina`, `studio-display` |
| `Tokyonight 13 tight` | IntoneMonoNF 13 | 1.33 | `tokyonight`, `2k` |
| `Tokyonight 16` | IntoneMonoNF 16 | 1.7 | `tokyonight`, `4k` |
| `Tokyonight 16 tight` | IntoneMonoNF 16 | 1.5 | `tokyonight`, `retina`, `studio-display` |
| `Tokyonight 20` | IntoneMonoNF 20 | 1.7 | `tokyonight`, `2k` |

Every Tokyonight monitor size keeps its old font and spacing. `Everforest 11…20` have the same names, sizes and tags with `MesloLGSDZNFM-Regular`, and Everforest's own line spacing (Meslo needs more room than IntoneMono): 1.75 for 11 and 13, 1.9 for 16 and 20, and for the tight variants Tokyonight's tightening scaled onto those (13 tight 1.55, 16 tight 1.7; no earlier values to keep). Everforest used 12 and 16 so far; the shared size scale keeps the menus the same for both themes. Tune spacing in the UI; the change lands in the repo (ADR 0004).

14 profiles instead of 17, and a colour change is made once per theme.

(First built with four sizes per theme, merging 13 and 16 across monitors; that loosened retina/Studio Display big from 1.5 to 1.7 and 2k small from 1.33 to 1.5, which left a band of empty space under tmux's status bar. The tight variants were added the same day.)

### One profile for light and dark

iTerm 3.5+ keeps two colour sets in one profile (`Use Separate Colors for Light and Dark Mode: true`, keys `Ansi 0 Color (Light)`, `Ansi 0 Color (Dark)`, …) and follows the macOS appearance live.

- **Everforest:** dark from `Everforest Dark` (the "soft" background, `#333C43`), light from `Everforest Light`. `Everforest Dark - 4k` used a different background (`#293136`) and is dropped.
- **Tokyonight:** dark from today's `Tokyonight (Night)`. There's no light set in the repo: take Tokyonight Day from tokyonight.nvim's `extras/iterm/` (same source as the Night colours).
- **`THEME` goes.** No `Initial Text` in any profile, and the `vim.opt.background = vim.env.THEME or "dark"` lines in both Neovim `options.lua` files are removed. Until the follow-up idea (task 36) lands, Neovim falls back to its own background detection at startup (it asks the terminal for its background colour, Neovim 0.10+).

### Default per machine

A `This Mac` dynamic profile with a fixed GUID, whose parent is chosen per machine. Not called `Default`: iTerm names its own regular profile that, and name lookups (AppleScript, `Dynamic Profile Parent Name`) would hit either. The shared plist always points at it, so its value never flips between machines.

1. **First-run answer** in `.chezmoi.toml.tmpl`:

   ```
   [data.iterm]
     {{- $sizes := list "Tokyonight 11" "Tokyonight 13" "Tokyonight 16" "Tokyonight 20" "Everforest 11" "Everforest 13" "Everforest 16" "Everforest 20" }}
     defaultProfile = {{ promptChoiceOnce . "iterm.defaultProfile" "iTerm default profile" $sizes (ternary "Tokyonight 16" "Tokyonight 11" $isWork) | quote }}
   ```

   A choice from the size profiles, so a typo can't reach the file. The list is written out in the template and has to follow the profile files; the host check below fails when they differ. Personal keeps today's 11pt; work gets 16pt. Changed later in `~/.config/chezmoi/chezmoi.toml` + `chezmoi apply`.

2. **`zz-default.json.tmpl`**, a rendered copy (not a symlink), loaded last:

   ```json
   {
     "Profiles": [
       {
         "Name": "This Mac",
         "Guid": "B45E0000-0000-4000-8000-000000000002",
         "Dynamic Profile Parent Name": {{ .iterm.defaultProfile | quote }},
         "Dynamic Profile Parent GUID": {{ $guid | quote }},
         "Tags": [],
         "Rewritable": false
       }
     ]
   }
   ```

   `$guid` is looked up from the chosen profile's file (`include` + `fromJson` on `linked/iterm2/DynamicProfiles/*.json`), so the GUID isn't repeated in the template. It holds no settings of its own: font and colours are changed on the size or theme profile it points to, which stay rewritable and synced. `Tags: []` keeps it out of the monitor submenus it would otherwise inherit.

3. **Shared plist:** `Default Bookmark Guid` → `B45E0000-0000-4000-8000-000000000002`, and `New Bookmarks` holds only `iTerm defaults` (`B45E0000-0000-4000-8000-000000000000`: name, GUID, tag `base`).

### Files

```
linked/iterm2/DynamicProfiles/
  00-base.json        Base (+ the moved keys)
  everforest.json     Everforest, then Everforest 11/13/16/20 (parent first in the file)
  tokyonight.json     Tokyonight, then Tokyonight 11/13/16/20
private_Library/Application Support/iTerm2/exact_DynamicProfiles/
  symlink_00-base.json.tmpl, symlink_everforest.json.tmpl, symlink_tokyonight.json.tmpl
  zz-default.json.tmpl
```

- `catppuccin`, `cyberdream`, `one-dark`, `rigel`, `solarized` and their symlink templates are deleted.
- The target folder becomes `exact_`, so chezmoi removes the five dropped symlinks on machines that have them (else they dangle). Nothing else lives there: profiles made in the UI go to the main plist (ADR 0004).
- Existing GUIDs are kept where a profile maps over (`Tokyonight 11` keeps `- 4k small`'s, `Tokyonight 13` keeps `(Night)`'s, …); the rest are new.
- Generated by a one-off script from today's files, like the ADR 0002 port, then a round-trip check: every size profile resolves to the same colours and font as the old profile it replaces (allowing the two spacing changes above).

### Tests

- Host, `test/host/45-iterm.sh` rewritten for the new shape:
  - the plist's only regular profile is `iTerm defaults` with its fixed GUID; `Base`'s parent is it;
  - every dynamic profile sets both parent keys, and the GUID belongs to the profile the name names, loaded earlier;
  - theme profiles: parent `Base`, `Use Separate Colors for Light and Dark Mode` true, both `(Light)` and `(Dark)` colour sets;
  - size profiles: parent is a theme in the same file, `Normal Font` set, no `… Color` keys (colours only come from the theme; iTerm adds `Use Separate Colors…` on a rewrite, which is allowed);
  - every monitor tag (`retina`, `2k`, `4k`, `studio-display`) has exactly two sizes per theme;
  - no profile sets `Initial Text`;
  - the plist's `Default Bookmark Guid` is the `This Mac` GUID;
  - the `defaultProfile` choice list in `.chezmoi.toml.tmpl` is exactly the size profiles in `linked/iterm2/DynamicProfiles/`, and `zz-default.json` rendered for both profiles names one of them (a rename would otherwise make iTerm fall back to the default profile as parent, with an error dialog).
- `test/expected/{personal,work}/config.toml` and `managed.txt` snapshots updated.
- VM guided step: default profile has the expected size (11 personal, 16 work); switching macOS to light mode changes the colours of an open window.

## Verified (2026-10-16, Tart VM, Sequoia 15.7.7, iTerm 3.7.5)

Throwaway profiles shaped like the proposal (`Base` → `T` → `T 11`/`T 16`, plus the per-machine profile), read back over AppleScript: each profile opened in a window of a fixed pixel size, then its background colour and how many columns × rows fit (the font size).

| Check | Result |
|---|---|
| Nested dynamic parents | Works: the per-machine profile → `T 16` → `T` → `Base` resolves every level's font and colours |
| `(Light)`/`(Dark)` colours from a parent | Inherited; open windows switch live when macOS changes appearance |
| Load order | Parents must load first (files by name, profiles in file order). Otherwise iTerm shows a "Dynamic profile error" dialog ("references unknown parent name … Using the default profile as parent") |
| `"Tags": []` | Overrides the inherited tags: the per-machine profile shows at the top of the Profiles menu only |
| Changing the per-machine profile's parent while iTerm runs | Picked up live and kept after a restart; the stored `Default Bookmark Guid` doesn't change |
| Name `Default` | Clashes with the regular `Default` profile iTerm creates on first launch when its prefs have none |
| `Base` without a parent | **Broken.** After any reload while iTerm runs (editing any profile file), `Base` took the default profile's settings, parent included (`Base` → `T 16`), and every profile under it inherited them. A dynamic profile with no parent inherits from the default profile, and here the default is a descendant of `Base`. Fixed by giving `Base` a regular parent (`iTerm defaults` in the plist): clean through live edits and restarts |
| UI edit of a size profile (ADR 0004 rewrite) | With only `Dynamic Profile Parent Name` set, the rewrite copied the theme's colours and `Base`'s `Columns` into `T 16` and set its parent GUID to `Base`'s parent. With both parent keys on every profile, it wrote only the font (+ `Use Separate Colors…`); the other files were untouched |

**Today's setup has the parentless `Base` too**, with the default (`Tokyonight (Night) - 4k small`) as its child: likely the cause of task 32's stripped profile. On this Mac it never showed: the stored default here is iTerm's own regular `Default`, not the repo's.

## Options considered

### Profile layout

| | Two levels, one profile per monitor × size (today) | **Base → theme → size, monitors as tags** | One profile per theme, size only per machine |
|---|---|---|---|
| Profiles (2 themes) | 2 × 8 = 16 | 2 + 2 × 6 = 14 | 2 |
| Colours stored | Once per profile | Once per theme | Once per theme |
| Browse by monitor in the Profiles menu | Yes | Yes | No; Cmd+/- per session |

### Default per machine

| | **Per-machine `Default` child** | `Default Bookmark Guid` per machine (`defaults write`) | Template the plist | Switch font by display (iTerm Python API) |
|---|---|---|---|---|
| Survives iTerm save-on-quit | Yes, plist value is the same everywhere | No, flips in git | No: a rendered copy breaks UI sync of global settings | n/a |
| Custom code | One small template + one answer | Script + guard against drift | Changes ADR 0003's plist setup | A script running all the time, API server on (off by design) |
| Follows the monitor on the fly | No | No | No | Yes |

iTerm's Automatic Profile Switching matches host, user, path and job, not displays. Not worth a script while the work laptop is almost always docked; on an undocked day, pick `Profiles > retina > …`.
