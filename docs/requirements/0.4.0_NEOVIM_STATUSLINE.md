# 0.4.0 Neovim statusline

Status: implemented 2026-10-16 (task 39; tmux-status.nvim a04aabe). LazyVim config only; `nvim-legacy` left as is.

## Goal

Inside tmux, Neovim hides tmux's status bar (tmux-status.nvim) and its lualine takes its place, so the bar must look like tmux's (`tmux/themes/minimal.tmux.conf` + `components/clean.tmux.conf`): same information, colours and spacing, in every colour scheme and in light and dark, following the switches of `0.3.0_COLOUR_SCHEME_SYNC.md`.

## Design

- **Layout** (`plugins/ui.lua`, unchanged from nvim-legacy): mode, branch, file on the left; tmux windows in the middle (`%=`); selection, diagnostics, progress, location; then battery, date and time, session, three spaces apart with one trailing, as tmux's `status-right`. Outside tmux the tmux parts hide and a clock shows.
- **Theme** `lua/lualine/themes/vizion.lua`: the loaded scheme's own lualine theme (through lualine's `auto`), with no backgrounds (tmux: `status-style bg=default`) and the mode as coloured text, not bold, instead of a block (except `inactive`, whose colour is a background). Everforest takes section `b`'s foreground for `c`, as nvim-legacy. Lualine runs theme files again on every `ColorScheme` and `'background'` change, so it follows the scheme.
- **Colours** `lua/config/status_colours.lua`: read from the tmux theme of the loaded scheme and `'background'` (`~/.config/tmux/themes/<scheme>-<dark|light>.tmux.conf`, the file tmux itself sources), so both bars share one source, in and outside tmux. tmux's roles:

  | Part | tmux option |
  |---|---|
  | active window | `@text_selected` |
  | previous window (`-` flag) | `@text_unselected_recent` |
  | other windows | `@text_unselected` |
  | session | `@text_active` |
  | date and time | `@text_secondary` |
  | battery (no colour in tmux) | `@text_main` |
  | active tab (`VizionTabActive`) | `@text_selected` |

  Given to tmux-status.nvim as a `colors` function with `bg = "NONE"`; the plugin calls it again on every `ColorScheme`.
- **`StatusLine` background cleared** on every `ColorScheme`: Neovim fills what statusline highlights leave unset from `StatusLine`, which would otherwise put the scheme's statusline shade (e.g. `#16161e`) behind the whole bar.
- **Tabline** keeps the scheme's `TabLine` background (no tmux counterpart; as nvim-legacy).

## tmux-status.nvim changes

Needed upstream (christopher-francisco/tmux-status.nvim): its `ColorScheme` callback concatenated `value.fg`/`value.bg`, so the plain colour strings its README documents (and nvim-legacy passes) crashed it, and highlights only appeared after the next `:colorscheme`. Now a colour is a string (foreground) or `{ fg?, bg? }`, `colors` may be a function, and highlights are set at setup too.

## Tests

- **Host** (`test/host/46-colour-schemes.sh`): for every scheme and light/dark, the colours `status_colours.lua` reads equal the shell's resolution of the tmux theme file.
- **By hand** (private tmux server, 2026-10-16): Tokyonight Night, then `apply()` to Everforest light, Tokyonight light, Everforest dark: every part in the tmux theme's colour, no background codes in the bar, inactive tabs readable; outside tmux the clock shows and the tmux parts hide.

## Not covered

- tmux centres the windows on the whole bar (`status-justify absolute-centre`); lualine's `%=` centres them between the left and right parts, so they sit off-centre when those differ in width.
- Program name and tmux's mode prompts (Pending/Copy/Sync): not shown in Neovim.
