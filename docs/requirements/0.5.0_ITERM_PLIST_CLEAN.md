# 0.5.0 iTerm plist stays slim

Status: implemented 2026-10-16 (task 37, ADR 0008). VM check runs with the next full `test/run.sh`.

## Goal

The shared `linked/iterm2/com.googlecode.iterm2.plist` keeps only global settings and the `iTerm defaults` profile (ADR 0002, 0006) in git, even though every iTerm save writes a resolved copy of each dynamic profile into its `New Bookmarks`.

## Design

- **Filter.** `.gitattributes`: `linked/iterm2/com.googlecode.iterm2.plist filter=iterm-plist`. Clean command `bin/iterm-plist-clean.sh` (git runs it from the repo root): drops `New Bookmarks` entries whose `Is Dynamic Profile` is true, then `plutil -convert xml1`. No smudge.
- **Setup.** `run_onchange_after_30-macos.sh.tmpl` (group `gui`) runs `git -C <source> config filter.iterm-plist.clean bin/iterm-plist-clean.sh` and `filter.iterm-plist.required true`.
- **In place.** `bin/iterm-plist-clean.sh FILE…` cleans files in place (quit iTerm first: it saves over the file on quit).
- **Layout.** The stored plist is in `plutil`'s XML layout, the same as iTerm's saves, and is a fixed point of the filter.
- `bin/` is repo-only (`.chezmoiignore`).

## Restart notice

iTerm reads the plist only at launch (dynamic profiles reload live), and keeps the save mode "when quitting" (`NoSyncNeverRemindPrefsChangesLostForFile_selection` = 0): on quit it asks before overwriting a plist that changed since launch, while "automatically" writes over it with no check after any setting change. So after a pull that changes the plist, iTerm has to be restarted.

`run_after_35-iterm-restart.sh.tmpl` (group `gui`, every apply) prints to stderr, when iTerm is running and the plist's mtime is later than iTerm's start (from `ps -o etime`), to restart iTerm and to choose Discard Local Changes if it asks to overwrite. Silent otherwise. It also shows after iTerm itself wrote the plist while running (Save Now) or after an in-place clean; harmless.

The macOS settings script's comment now says how its iTerm `defaults write`s fare: at launch iTerm replaces every syncable setting with the plist's values, so a written setting only lasts if the plist has it (or iTerm was running and saves it on quit).

## Tests

- Host (`45-iterm.sh`): the plist checks read the plist through the filter; git applies the filter to the plist (`check-attr`); a plist with two planted dynamic profiles comes out with only `iTerm defaults`; the stored (index) plist is unchanged by the filter. `20-render.sh` shellchecks `bin/*.sh` and, like every script, the rendered restart notice.
- VM (`assert.sh`): the source repo's `filter.iterm-plist.clean` is set.
- Checked by hand on this Mac 2026-10-16: a plist bloated with this Mac's 16 saved dynamic profiles (21.5k lines) cleans to the stored one; the restart notice prints for a plist newer than iTerm's start and nothing for an older one; `git diff` shows no change for a copies-only save (`git status` lists the file until `git add` refreshes its size; found after the first real save and in-place clean, 2026-10-16); `git add` from a subfolder runs the filter.
